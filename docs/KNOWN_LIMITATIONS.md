# TraceGuard AI — Known Limitations & System Scope

This document provides transparent disclosure of design constraints, theoretical boundaries, and intentional simplifications in the current TraceGuard AI MVP.

---

## 1. Abstract HTTP Protocol Lifecycle Scope
- **Not a Full RFC HTTP Parser:** The FSM engine models an educational, abstract 8-state HTTP connection lifecycle (`IDLE`, `CONNECTED`, `REQUEST_RECEIVED`, `AUTH_CHECKED`, `AUTH_FAILED`, `RESPONSE_SENT`, `ERROR`, `CLOSED`).
- It does **not** parse chunked transfer encodings, multi-part headers, HTTP/2 multiplexing, or HTTP/3 QUIC frames. It operates on structured protocol event sequences.

---

## 2. Packet Capture & Hardware Sniffing
- **Simulated & Tabular Ingestion:** The current MVP does not bind to raw network interfaces via PCAP / libpcap / promiscuous NIC drivers.
- Ingestion occurs via:
  1. Synthetic simulated traffic generated by the built-in deterministic Markovian generator (`app/simulator/generator.py`).
  2. CSV/JSON file uploads representing recorded network event logs.

---

## 3. Synthetic Dataset & ML Model Limitations
- **Synthetic Training Data:** The model is trained on 600 synthetic sessions (480 train / 120 test) generated with fixed random seeds (`seed=42`).
- **Isolation Forest Specifics:**
  - Contamination is set to `0.1` (10%).
  - The model achieves an F1-score of **0.5312** on the synthetic test set, reflecting the unsupervised nature of Isolation Forests in separating high-density benign clusters from edge deviations.
  - On completely unseen zero-day attack templates, it achieves a **68.0% detection rate**.
- **Real-World Calibration:** Production deployment requires retraining against live PCAP session features extracted from enterprise perimeter logs (e.g. Zeek / Suricata / Bro logs).

---

## 4. Multi-Tenant Isolation & Authentication
- **Demo-Ready Auth:** The system provides JWT bearer tokens and password hashing via bcrypt, with seeded demo credentials (`demo` / `traceguard2024`).
- **Tenant Scope:** Data isolation is currently single-tenant / workspace-wide in SQLite. Multi-tenant database schemas, per-organization role-based access control (RBAC), and enterprise SSO (SAML/OIDC) are planned for future major releases.

---

## 5. Storage & Production Scaling
- **Database Engine:** Uses SQLite via SQLAlchemy. Suitable for local demonstrations, automated testing, and single-node workloads.
- **Production Roadmap:** For deployments exceeding 50,000 events/sec, transition to PostgreSQL / TimescaleDB for event persistence and Redis for pub/sub WebSocket message fanout.
